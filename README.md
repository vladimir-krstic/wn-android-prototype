# White Noise Android Prototype

A native Android prototype of White Noise built with Kotlin, Jetpack Compose,
Material 3, and AndroidX. It preserves accepted iOS and production Android
product capabilities while using Android navigation and system interactions.

Product state is deterministic and in memory. The app has no backend, network
transport, real authentication, cryptography, or durable product storage.
Device-owned media, sharing, scanning, and speech interactions use the approved
Android integrations. The default identity is monochrome; optional appearance
colors and bundled fonts follow the recorded product decisions.

## Setup

Use an Android SDK with platform 37 and a Java installation capable of starting
the checked-in Gradle wrapper. The daemon criteria select JDK 21; application
Java/Kotlin bytecode targets Java 17. Configure the SDK with your local
`local.properties` (`sdk.dir`) or Android SDK environment. Python 3 is required
for the repository verification scripts. Initial Gradle dependency/toolchain
resolution needs internet access; this does not enable application networking.

The app supports API 23 and later and compiles/targets API 37. Dependency pins
live in [the version catalog](gradle/libs.versions.toml); the Gradle version is
owned by [the wrapper](gradle/wrapper/gradle-wrapper.properties). Material 3's
approved prerelease pin preserves API 23 support and Expressive menus. Do not
replace compatibility pins solely to clear newer-version lint warnings.

Application ID: `dev.ipf.whitenoise.android.prototype`.
Namespace: `dev.ipf.whitenoise`.

## Build and verification

Run from the repository root:

```sh
python3 -m unittest discover -s scripts -p 'test_*.py'
./scripts/verify_locale_resources.py
./gradlew testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
```

For a clean host gate:

```sh
python3 -m unittest discover -s scripts -p 'test_*.py'
./scripts/verify_locale_resources.py
./gradlew clean testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
```

Unit tests execute on the host. Instrumentation tests are compiled and packaged
by these commands. Debug outputs:

- App: `app/build/outputs/apk/debug/app-debug.apk`
- Tests: `app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk`
- Unit results: `app/build/reports/tests/testDebugUnitTest/index.html`
- Lint: `app/build/reports/lint-results-debug.html`

The release notice pipeline can be checked with `./gradlew assembleRelease`;
release dependency notices are generated by the existing OSS Licenses plugin.

Only when the user's **current request explicitly authorizes device/emulator
testing**, run:

```sh
./gradlew connectedDebugAndroidTest
```

That command is documentation, not standing authorization to use `adb`, start
an emulator, install/launch the app, interact with a device, or take screenshots.
An attached phone or earlier inspection request does not carry authorization
forward. See [AGENTS.md](AGENTS.md) for the full workflow.
